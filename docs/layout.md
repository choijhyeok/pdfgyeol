# 페이지 영역과 읽기 순서

```python
from pdfgyeol import extract_pdf, infer_page, iter_layout

document = extract_pdf("notes.pdf")
for page, layout in zip(document.pages, iter_layout(document.pages)):
    fragments = {fragment.id: fragment for fragment in page.fragments}
    # 아래 문자열은 추론한 순서의 원문 조각 연결이며 공백/개행을 생성하지 않는다.
    text = "".join(fragments[id].text for id in layout.ordered_fragment_ids())
    print(page.page_number, text, layout.warnings)

first_page_layout = infer_page(document.pages[0])
```

레이아웃 추론에는 `extract_pdf`가 반환한 `Page`를 사용한다. 단과 표는 페이지의 글자·벡터 배치만으로 추론한다. `extract_pdf`는 전체 원문을 메모리에 보관한다. `infer_page`와 `iter_layout`은 준비된 원문 페이지를 하나씩 처리하며 페이지 사이 상태나 캐시를 유지하지 않는다.

## 결과와 원문 소유권

`PageLayout`은 불변 타입이며 `page_id`, `lines`, `regions`, `tables`, `reading_order`, `alternatives`, `warnings`를 제공한다. 원문 텍스트와 개별 글자 좌표는 [추출한 원문 ID](extraction.md#원문과-id)로 참조한다. 새로 계산한 상자도 회전을 적용한 MediaBox의 왼쪽 위를 원점으로 하고 x는 오른쪽, y는 아래쪽으로 증가한다. 단위는 PDF point다.

- `TextLine.fragment_ids`: 기하적으로 묶은 글리프. 공백·겹쳐 찍힌 글리프·0폭 글리프도 소유한다. 정렬은 x 좌표와 원문 인덱스 순서다. 원문의 숨은 텍스트나 오버프린트를 제거하지 않는다.
- 텍스트 `Region.line_ids`: 줄을 이어 묶은 영역. 큰 글꼴은 `heading`, 일반 줄 묶음은 `text`다. 단은 `column_path`로 표시하며 재귀 분할의 왼쪽 0·오른쪽 1이다. 전폭 구분선 사이의 국소 단 소속을 뜻하며 문서 전체의 영구 단 번호는 아니다.
- 표 `Region.table_id`: 표를 한 덩어리로 참조한다. `Table.rows`의 각 셀은 `region_ids`를 가진다. 셀의 영역이 또 다른 표를 참조하면 중첩 표다. 원문은 가장 작은 포함 셀에 귀속되며 상위 셀에 복사하지 않는다.
- `TableCell`은 `row_index`, `column_index`, `row_span`, `column_span`을 가진다. 인덱스는 0부터 시작한다. 병합 셀은 시작 행에서 한 번만 나타나며 이후 행에 다시 넣지 않는다. 빈 셀도 남긴다. `inferred=True`는 원문의 선 없이 텍스트 정렬로 행 경계를 보완한 셀이다.
- `Table.vector_ids`는 표를 뒷받침하는 원문 도형 참조다. 부모·자식 표가 같은 도형을 증거로 참조할 수 있다. 텍스트 소유권과 다르다.

`reading_order`는 루트 영역 ID만 담는다. `ordered_fragment_ids()`는 루트 → 표의 행·셀 → 셀 영역 → 줄을 따라 원문 ID를 반환한다. 영역 레지스트리 전체를 다시 순회해 문자열에 더하면 중첩 내용을 중복 계산하게 되므로 이 소유권 경로를 사용해야 한다. `infer_page`는 반환 전에 모든 원문 ID가 정확히 한 번 도달하는지 검사한다. 입력의 중복 ID는 `ValueError`, 내부 원문 소유권 오류는 `RuntimeError`로 드러낸다.

## 기하 규칙

1. stroke 선·사각형·직선 path와 얇게 채운 사각형을 가로/세로 테두리 증거로 변환한다. Bézier 곡선과 넓은 채움은 테두리로 만들지 않는다. pdfplumber의 선 병합·교차점·닫힌 셀 탐색 함수를 사용한다.
2. 연결된 셀들을 표로 묶고, 다른 표의 셀 안에 엄격히 포함된 표를 자식으로 연결한다. 단 안의 표와 병렬 표는 각자의 상자로 유지한다. 한 개의 닫힌 상자만으로 표를 만들지 않는다.
3. 큰 몸통 셀들이 나란히 있고 좁은 레이블 열의 반복 줄과 이웃 열이 정렬되면 행 경계를 보완한다. 공백뿐인 레이블 줄은 원문에 남기되 행 시작 증거로 쓰지 않는다. 설명이 여러 줄이면 다음 레이블 전까지 같은 행에 남는다. 이 단계는 숫자·언어·보험 어휘를 요구하지 않는다.
4. 글리프를 중앙 높이·upright로 묶고 넓은 가로 간격에서 줄을 나눈다. 표 셀마다 독립적으로 줄을 만들어 옆 셀과 섞지 않는다.
5. 줄과 표 상자의 반복 가로 공백에서 단 경계를 찾는다. 임시 줄이 경계를 가로지르면 경계의 글리프 간격이 8pt와 줄 글꼴 크기 중 큰 값 이상이고, 양쪽 조각 각각의 위아래에 시작점과 글꼴 크기가 비슷한 인접 줄이 있을 때 두 줄로 나눈다. 나머지 경계 횡단 줄과 표는 세로 구간의 구분자로 삼는다. 각 구간에서 왼쪽 단 전체, 오른쪽 단 전체 순으로 읽고 필요하면 재귀 분할한다. 표를 끝내면 같은 단의 다음 본문으로 돌아간다.
6. 같은 단에서 글꼴 크기·들여쓰기·줄 간격이 가까운 연속 줄을 영역으로 묶는다. 표와 큰 제목은 영역을 나눈다.

`LayoutConfig`로 줄·테두리 허용 오차, 최소 단 지지 줄 수, 표 탐색 상한을 바꿀 수 있다. 기본값은 각각 2pt, 2pt, 2개, 테두리 1,200개, 교차점 4,000개다. 과도한 도형 페이지는 `table_edge_budget_exceeded` 또는 `table_intersection_budget_exceeded` 경고와 함께 표 추론을 건너뛰고 텍스트는 모두 남긴다. 일반 PDF의 페이지 수 자체에는 제한을 두지 않는다.

## 국소 대안

테두리 없이 양쪽에 2~3줄이 같은 높이에 정렬된 경우 `sparse_aligned_blocks` 후보를 만든다. 4~16줄은 양쪽의 줄이 일대일로 정렬되고 줄 사이 여백이 충분할 때 검토한다. 짧은 왼쪽 항목의 시작점이 일정하고 짧은 오른쪽 항목이 왼쪽이나 오른쪽으로 정렬돼 있으면 `aligned_label_value_rows` 후보를 만든다. 공백뿐인 줄은 원문에 남기며 항목으로 세지 않는다. 이 조건은 촘촘하거나 열 너비를 채우는 본문에 행 순서 후보를 추가하지 않기 위한 것이다. 길거나 누락된 행이 있는 무테두리 목록은 이 규칙의 범위를 벗어난다.

두 경우 모두 기본 `columns`와 대안 `rows`를 결정적으로 기록한다. 각 후보의 `region_ids`는 같은 원문 영역의 서로 다른 순열이며 텍스트를 복제하지 않는다. 후보에 포함된 줄은 영역으로 합치지 않아 순서를 독립적으로 바꿀 수 있다.

`scope_id`는 페이지 또는 표 셀 ID이며, 후보는 그 범위의 정규 순서에 있는 연속 부분 구간을 교체하기 위한 것이다. `infer_page` 결과에는 대안 후보와 기본 순서(`default_index=0`)가 담긴다. 선택·보류·명시적 모델 호출은 [`resolve_page`](decision.md)에서 처리한다. 모든 모호함을 탐지한다는 보장은 없다.

## 검증과 한계

합성 PDF는 정원·관측소·실험 기록을 직접 생성한다. 전폭 제목 전후의 2단, 3단, 단 안 표 뒤 본문 재개, 병렬·중첩 표, 병합/빈 셀, 가로선 없는 몸통 행과 줄바꿈, 채움 도형 테두리, 오버프린트·공백, 국소 대안의 원문 보존을 검사한다. 원문 보존은 기본 순서와 대안 순열 모두에서 검사한다.

규칙은 가로 LTR 문서 중심이다. 비-upright 텍스트는 보존하지만 `non_upright_text_geometry_order` 경고를 내며 자연스러운 세로/RTL 읽기 순서를 보장하지 않는다. 단 경계를 찾을 만큼 분리된 줄이 부족하거나, 위아래의 가까운 줄로 양쪽 단을 확인할 수 없으면 좁은 단 사이에서 글자가 한 줄에 섞일 수 있다. 전폭 줄의 글자 간격과 주변 정렬이 단과 일치하면 줄을 잘못 나눌 수 있다. 위첨자·혼합 크기, 가까이 붙은 표·도표, 경계를 가로지르는 글자, 불완전한 테두리와 완전 무테두리 표에서도 잘못된 줄·단·셀 귀속이 가능하다. 완전 무테두리 표는 확정 셀 대신 텍스트와 일부 순서 대안으로 남을 수 있다. 이미지·주석은 읽기 순서 영역으로 만들지 않으며 원문 `Page`에 남는다. 페이지 사이에 이어지는 표나 문단은 아직 합치지 않는다.
