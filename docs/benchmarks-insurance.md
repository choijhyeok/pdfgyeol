# 보험 약관 PDF 파서 비교

보험 약관 PDF 6개에서 선택한 8쪽을 비교했습니다. 문서마다 1쪽씩 읽기 순서를 확인했고, 그중 두 문서에서 다른 1쪽씩 표를 확인했습니다. 보험사는 A~E로, 문서는 `A-1`처럼 표기합니다. 같은 문서에는 모든 비교에서 같은 식별자를 사용합니다.

읽기 순서와 표 비교에 기록된 버전은 pdfgyeol 0.1.0, pdfplumber 0.11.11, PyMuPDF 2.2입니다.

## 읽기 순서

파서 출력을 확인하기 전에 페이지 이미지에서 읽는 순서대로 기준 구절 6개를 골랐습니다. 기준 구절과 추출 텍스트는 유니코드 NFKC로 정규화하고 공백과 제어 문자를 제거했습니다. 구절의 첫 등장 위치를 사용하되, A-1에서 본문에 먼저 인용된 제목 하나는 실제 제목에 해당하는 마지막 등장 위치를 사용했습니다. 구절 쌍 15개 중 두 구절이 모두 추출되고 기준 순서대로 나온 쌍마다 1점으로 계산했습니다.

pdfgyeol은 pdfplumber에서 추출한 글자와 좌표에 레이아웃 추론을 적용한 뒤 읽기 순서로 조합한 텍스트를 사용했습니다. pdfplumber는 `extract_text()`와 `extract_text(use_text_flow=True)`를, PyMuPDF는 `get_text()`와 `get_text(sort=True)`를 각각 비교했습니다.

| 문서 | pdfgyeol | pdfplumber 기본 | pdfplumber `use_text_flow=True` | PyMuPDF 기본 | PyMuPDF `sort=True` |
| --- | ---: | ---: | ---: | ---: | ---: |
| A-1 | 15/15 | 12/15 | 15/15 | 15/15 | 12/15 |
| A-2 | 15/15 | 12/15 | 15/15 | 15/15 | 12/15 |
| B-1 | 15/15 | 15/15 | 15/15 | 15/15 | 15/15 |
| C-1 | 15/15 | 15/15 | 15/15 | 15/15 | 15/15 |
| D-1 | 15/15 | 15/15 | 11/15 | 11/15 | 15/15 |
| E-1 | 15/15 | 15/15 | 15/15 | 15/15 | 15/15 |
| 합계 | 90/90 | 84/90 | 86/90 | 86/90 | 84/90 |

pdfplumber의 텍스트 흐름 옵션과 PyMuPDF의 정렬 옵션을 적용했을 때 점수 변화의 방향은 페이지에 따라 달랐습니다.

## 표 추출

pdfgyeol에서 감지한 표의 셀 텍스트, pdfplumber의 `extract_tables()`, PyMuPDF의 `find_tables()`로 찾은 각 표의 `extract()` 결과를 비교했습니다. 셀 텍스트는 읽기 순서와 같은 방식으로 정규화했습니다.

| 문서 | 비교 항목 | pdfgyeol | pdfplumber | PyMuPDF |
| --- | --- | ---: | ---: | ---: |
| A-2 | 지정한 두 행의 항목명과 수량 셀 | 13/13 | 13/13 | 0/13 |
| E-1 | 표 양쪽의 번호와 항목명 | 51/51 | 0/51 | 1/51 |

- A-2는 첫 항목명이 있는 행부터 연속한 두 행을 검사했습니다. 항목명과 수량을 포함한 기준 셀 13개 중 같은 행과 열의 값이 정확히 일치한 셀마다 1점을 부여했습니다.
- E-1은 표 양쪽에 있는 번호 51개를 대상으로 했습니다. 같은 행의 인접한 두 셀에서 번호가 일치하고 다음 셀이 해당 항목명의 기준 문자열로 시작하면 번호당 1점을 부여했습니다. 가운데점 표기 차이를 정규화했고, 같은 번호가 여러 번 일치하면 한 번만 계산했습니다.

## 처리 시간

C-1의 25쪽 전체를 같은 머신에서 텍스트로 추출했습니다. pdfgyeol은 `parse_pdf(path).text`를 호출했고, pdfplumber와 PyMuPDF는 각각 모든 페이지의 기본 `extract_text()`와 `get_text()` 결과를 이어 붙였습니다. 라이브러리마다 1회 예열한 뒤 실행 순서를 바꿔 가며 3회 측정했습니다. 각 측정 전에 `gc.collect()`를 호출하고 `perf_counter()`로 경과 시간을 쟀습니다. 측정 구간은 PDF 열기부터 전체 텍스트 결과를 얻기까지이며, 라이브러리 임포트와 JSON·표 직렬화는 측정 구간 밖에 있습니다.

| 파서 | 경과 시간 중앙값 |
| --- | ---: |
| pdfgyeol | 1.028초 |
| pdfplumber | 0.948초 |
| PyMuPDF | 0.119초 |

## 결과를 해석할 때

읽기 순서 점수는 선택한 6쪽의 기준 구절 순서에, 표 점수는 선택한 두 표의 지정 셀과 항목에 한정됩니다. 처리 시간은 문서 한 개에서 잰 값입니다. 다른 레이아웃과 스캔 PDF, 문서 전체의 텍스트·표 정확도, 보험 약관 구조 표시와 Decision 옵션의 성능을 평가하려면 별도 검증이 필요합니다.
