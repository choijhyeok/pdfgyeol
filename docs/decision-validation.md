# Decision 평가 결과

2026-11-27에 직접 생성한 PDF로 Decision-1.1의 읽기 순서 판정을 평가했다.

후속 평가에서도 실제 순서 교정은 0건이었다. 기본 `min_score=0.55`, `min_margin=0.10`을 유지하며, 아래 독립 평가 결과를 기본값 변경의 근거로 사용하지 않는다.

## 평가한 후보

`aligned_label_value_rows`는 짧고 띄어진 정렬 항목 4~16개에서 단별 순서 `columns`와 행별 순서 `rows`를 만든다. `sparse_aligned_blocks`도 페이지 또는 셀 안의 같은 영역들을 두 순서로 제시한다. 4·8행 측정 PDF와 레이아웃 회귀 검사에서 후보가 가리키는 영역과 기본 읽기 순서를 확인했다. 중첩 셀과 서로 다른 여러 범위의 적용은 별도로 검사했다.

## 자동 검사

초기 구현 전체 검사 93개 통과, strict mypy 6개 소스 파일 통과, diff 공백 검사 통과. 테스트·라이브 검증 외 추가 의존성은 없다.

가짜 제공자는 대안을 실제 적용해 문자 ID를 기대 순서로 재배열하는지 확인한다. 부모·형제 셀, 루트의 전후 영역, 원문 객체, 줄·영역·표 좌표가 유지되는지 검사한다. 출처 ID의 `Counter`가 입력과 같고 각 ID가 한 번만 나오는지 검사한다. 실패·동점·낮거나 근접한 점수·비정상 수치·누락/추가 키·중복 JSON 키·원문 변경 시도·타임아웃·429·503·중복/순환 소유권·다른 셀 침범은 적용되지 않는다. 기본 모드와 무후보 모드는 환경/클라이언트 생성도 하지 않는다. 응답 실패 뒤 다른 국소 대안은 계속 처리한다.

## 실제 Decision-1.1 호출

소유자가 허용한 외부 `.env`의 endpoint·키·배포명을 메모리에서만 읽었다. endpoint·키·응답·발췌는 출력·복사·커밋하지 않았다. 다음 명령의 경로는 운영자가 허용한 파일로 바꿔 실행했다.

정답은 네트워크 호출 전 고정했다. 4행·8행 측정 목록과 중첩 셀은 행별 읽기가 정답이며 기본 단별 순서는 틀린 표본이다. 짧은 독립 본문 단과 무후보 대조군은 기본 순서가 정답이다. 기본 `min_score=0.55`, `min_margin=0.10`에서 네 응답 모두 보류되어 실제 대안 적용·품질 개선은 입증되지 않았다. 긍정적인 적용·순서 검증은 가짜 제공자 테스트의 결과다. 이 작은 개발 표본으로 실제 문서 정확도나 임곗값 보정을 주장하지 않는다.

앞선 검증 도구 실행은 네 영역의 요청 후 마지막 대조 PDF가 뜻하지 않게 후보를 생성해 중단됐다. 대조군의 줄 간격을 수정하고, 모든 표본의 후보·정답을 가짜 제공자로 먼저 검사한 뒤 최종 실행을 완료했다. 중단된 실행의 응답은 집계하지 않았다. 전체 라이브 요청 시도는 두 실행 합계 8회이며 위 표는 완료된 4회만 나타낸다. 모델 점수에 맞춰 후보·정답·기본 임곗값을 바꾸지 않았다.

## 평가의 한계

호출·보류·국소 적용은 자동 검사로 확인했다. 실제 Decision-1.1 호출에는 합성 문서만 사용했고, 이 표본에서 실제 순서 교정은 관찰하지 못했다. 점수 보정과 실제 문서에서의 효과는 별도 평가가 필요하다.

## 후속 독립 평가: 신규 비보험 합성 항목

예제·정답·분할·판정 기준·비교 정책 하나를 라이브 요청 전에 `7dea854`에 고정했다. [공개 항목 정의와 판정 기준](../tools/decision_evaluation_protocol.json), [평가 도구](../tools/decision_evaluation.py)로 오프라인 사전검사를 재현할 수 있다. 당시 SHA-256은 `80669e4b01110f3d5b6b8438aadc36aa93e69ce9a3e0f0547497ab09721d29b9`다. 이 해시는 레이아웃 코드를 포함하므로 이후 단 경계 처리를 수정하면서 달라졌다. 수정 뒤에도 오프라인 사전검사 12개가 통과했으며, 아래 라이브 점수는 당시 실행의 기록이다. 예제는 전부 새로 작성했고 실제 문서·보험 자료는 사용하지 않았다.

개발 6개와 holdout 6개에 행 목록·독립 본문·저증거 각 2개를 배치했다. 행 목록은 작성 시 고정한 label/value 짝을 유지하는 `rows`, 본문은 별도로 작성한 두 문장을 각 단에서 이어 읽는 `columns`가 정답이다. 코드·이름만 놓인 저증거 항목은 의미상 유일한 순서를 주장하지 않으며 `deferred`만 성공으로 센다. 기하 기본값의 존재를 저증거 정답으로 사용하지 않았다.

사전검사에서 12개 모두 실제 순서 후보 묶음이 정확히 하나 생성되고, 양쪽 순열을 적용하면 미리 정한 문자열이 되는지 확인했다. 오프라인 검사에서 본문 예제의 짧은 바닥글이 단 안에 묶여 바닥글 폭을 늘렸다. 이후 후보·정답·도구를 고정했고 요청 후에는 수정하지 않았다.

기존 구조화 기하·발췌·질문·0.10 여유는 유지하고 절대 하한만 0.55에서 0.35로 낮추는 challenger 하나를 비교했다. 이전 개발 점수의 최고값이 0.55보다 낮았기 때문에 확인한 가설이며 확률 보정값은 아니다. 짧은 A/B 문자열로 바꾸는 방식은 사용하지 않았다. 라이브 응답은 항목당 한 번 받아 메모리에서 두 정책에 그대로 재사용했다. 최대 12회, 실패 시 재시도·항목 교체 없음으로 고정했으며 실제 12회 모두 유효 응답이었다. 최대 상태는 4,979 UTF-8 bytes였다.

개발 채택 조건은 유효 응답 6개, 행 교정 최소 1개, 모든 클래스 회귀 0개, 저증거 2개 모두 보류였다. 개발 결과는 행 교정 0개라 부적격으로 확정한 뒤 holdout을 호출했다. 사전 계획대로 같은 challenger의 holdout 결과도 한 번 측정했지만, 개발 부적격 상태를 바꾸거나 holdout으로 새 정책을 선택하지 않았다. Holdout에도 같은 조건을 적용했으며 행 교정 0개로 통과하지 못했다. 추가 후보·질문·임곗값 탐색이나 추가 호출은 하지 않았다.

### 클래스별 결과

‘성공’은 행·본문에서 정확한 전체 순서, 저증거에서 보류다. ‘교정/회귀’는 같은 응답에서 기존 정책의 성공 여부가 challenger에서 바뀐 수다. 본문의 기본 순서를 보류로 유지한 경우도 순서 성공으로 세므로 성공과 모델 확정을 구분한다.

| 분할 / 클래스 | 항목 | 기존 성공 → challenger 성공 | 교정 | 회귀 | 기존 보류 → challenger 보류 |
|---|---:|---:|---:|---:|---:|
| 개발 / 행 목록 | 2 | 0 → 0 | 0 | 0 | 2 → 2 |
| 개발 / 독립 본문 | 2 | 2 → 2 | 0 | 0 | 2 → 2 |
| 개발 / 저증거 | 2 | 2 → 2 | 0 | 0 | 2 → 2 |
| Holdout / 행 목록 | 2 | 0 → 0 | 0 | 0 | 2 → 2 |
| Holdout / 독립 본문 | 2 | 2 → 2 | 0 | 0 | 2 → 1 |
| Holdout / 저증거 | 2 | 2 → 2 | 0 | 0 | 2 → 2 |

행·본문 8개에서 정확한 순서는 기하 단독·기존 정책·challenger 모두 4/8이다. 저증거 4개는 두 정책 모두 보류했다. 기존 정책은 12개 모두 보류했고 challenger는 11개 보류, 본문 1개를 `kept_default`로 확정했다. 대안 순열을 실제 적용한 항목은 두 정책 모두 0개다. 성공 수 증가나 보류 감소를 실제 교정으로 바꿔 세지 않았다.

### 유지 결정과 검사

기본 0.55/0.10을 유지한다. 신규 개발·holdout 모두 교정 조건을 만족하지 못했고, 이 작은 합성 표본으로 배포별 낮은 절대 하한의 효과나 안전성을 입증하지 못했다. 실험 방법은 [명시적 임곗값 설정](decision.md)에 설명했다. 더 낮은 여유나 다른 하한을 holdout에 맞춰 시도하지 않았다.

각 정책에서 원문 객체·문자 ID 보존, 줄·영역·표·후보 불변, 활성 영역 밖 순서 불변, 비활성 호출 0회를 확인했다. 실패 응답 재사용·12회 예산·고정 예제 정답·교정/회귀 집계·저증거 선택 시 채택 거부를 오프라인 검사에 추가했다. 최종 전체 검사 97개, strict mypy 6개 소스 파일, `git diff --check` 통과. 기존 consent·privacy·fallback 계약과 런타임 기본값·기하 탐지는 변경하지 않았다.

항목 출처는 공개 합성 정의뿐이다. 승인된 설정은 메모리에서만 읽었고 파일 경로·키·endpoint·원시 응답·발췌·세션 정보·원본 문서는 공개 기록에 남기지 않았다. 임시 생성 PDF는 제거했다. 개발·holdout 각 클래스 2개뿐이며, 행 예제는 4줄·본문/저증거는 2줄이라는 형식 차이도 있어 도메인 일반화나 정확도 보정의 근거가 되지 않는다. 중첩 셀·장문·실제 문서 분포의 효과는 이번 독립 평가로 확인하지 않았다.
